# 0094: fast-v2, the fast subset without jailbreak_recognition and agentic_misalignment

Issue #497.

## Why

Camila, 2026-11-17: "exclude jailbreak and agentic". Measured on the fast subset (s3d-rl600,
2026-11-17): the two safety families take 23 to 38 minutes to judge after their readouts land,
against 1 to 13 minutes for the other 22, so they alone hold a fast run above 30 minutes; and
they change no ordering of the measured arms (without them each arm's fast macro moves by at
most 0.028: s3d .535 -> .538, rl-affw .491 -> .497, Q9 .478 -> .484, NLA .442 -> .449,
prompt-only .475 -> .480, J-lens .116 -> .119, logit lens .063 -> .067). agentic's fast
`pair_rate` also moves by about 0.07 between identical runs. `fast-v1` is frozen ("a new subset
is a new versioned file"), so this is `fast-v2`.

## Change

- New frozen file `evals/fast/fast_v2.json`: `version: "fast-v2"`, the 22 family entries of
  `fast_v1.json` other than `jailbreak_recognition` and `agentic_misalignment`, each entry
  identical to v1's (same `bank_sha`, `units`, `read_ids`, key order); `dropped_families` = v1's
  list plus the two (sorted as v1 sorts it); every other top-level key as in v1. 22 families,
  1,823 units; no remaining entry has a `positions` rule. `fast_v1.json` is not touched.
- `fast.py`: `VERSION = "fast-v2"`, `PATH` -> `fast_v2.json`; `VERSIONS = {"fast-v1": <v1 path>,
  "fast-v2": <v2 path>}`; `subset(version: str | None = None)` loads that version (default
  `VERSION`), cached per version. Every other function keeps using the default version.
  `--fast` therefore means fast-v2; `fast-v1` is not selectable from the CLI (its file stays for
  provenance and for tests of the position rules).
- Under `--fast` the two families are skipped like any family outside the subset
  (`NotInFast`, "<family>: not in fast-v2", exit 0 in `run`, exit 2 in `judge` as today for an
  out-of-subset family).
- Readouts sidecars: a file that declares `"fast": "fast-v1"` is accepted under fast-v2 for a
  family in fast-v2 (`fast.COMPATIBLE = {"fast-v1"}`: the 22 entries are identical, so the fast
  plan rows and the `plan_sha` are the same); it is still refused for any other declared value.
  A new file declares `"fast": "fast-v2"`. The `plan_sha` guard is unchanged.
- Results: stamped `config.fast_subset = "fast-v2"`. `results.macro` / `report` must not mix
  `fast-v1` and `fast-v2` rows: extend the existing fast / non-fast mixing guard to the subset
  version (a mixed directory is refused with a message naming both versions).
- **Retained on purpose:** the position-reduction machinery (`readplan` `fast_of` /
  `punct_special` / `is_fast_site`, `reads.fast_narrow`, `fast.position_stamp`,
  `runner.stamp_fast`'s `+fast-<kind>` suffix) stays in the code, unused by fast-v2 entries, so
  `fast_v1.json` and readouts read under it remain interpretable; the non-fast paths stay
  untouched (`tests/golden/plan_sha_pre_0090.json` still pins the plans).

## Invariants

- No prompt, fingerprint, cache key or `prompt_version` changes; for each of the 22 families a
  fast-v2 run makes exactly the calls a fast-v1 run made (a cache written under fast-v1 replays
  with 0 new calls) and gives the same value; only the `fast_subset` stamp differs.
- The strict ATI subset (`ati-subset-v2`) is still contained whole (neither dropped family is in
  it).
- `fast_v1.json` is byte-identical before and after.

## Tests

`tests/test_fast_subset.py` pins fast-v1 throughout (21 mentions; counts 24 / 1,996 / 2,351, and
tests that take their items from `fast.subset()[JB]` / `[AM]`). Sanctioned edits, and only these
kinds: (a) a count or version literal that describes "the fast subset" moves to the fast-v2
value (22 families, 1,823 units, the v2 read-item count computed from the file, `"fast-v2"`);
(b) a test that exercises the position rules or the two dropped families' entries reads them
from `fast.subset("fast-v1")` instead of `fast.subset()` and keeps every assertion; if such a
test drives the CLI with `--fast` on jailbreak / agentic, it is split: the rule-level assertions
stay on a v1-loaded entry (monkeypatching `fast.VERSION` / `fast.PATH` to v1 for that test is
allowed), and no assertion is dropped. List every edited pre-existing assertion in the report.
New tests:
- `fast_v2.json` equals `fast_v1.json` minus the two families (entry-for-entry equality, the
  `dropped_families` rule, the version string); `fast_v1.json`'s sha256 is pinned.
- `subset("fast-v1")` and `subset()` both load; unknown version raises.
- `--fast` on jailbreak_recognition / agentic_misalignment: skipped by `run`, exit 2 in `judge`
  with "not in fast-v2".
- a sidecar declaring `fast-v1` is accepted for a fast-v2 family and judged; one declaring
  `fast-v0` is refused; a produced file declares `fast-v2`.
- a result stamped `fast-v1` beside one stamped `fast-v2` is refused by the macro / report.
- a toy family's cache written with the subset version patched to v1 replays under v2 with 0
  new calls and the same value.
- ATI containment under v2.
